# 07 — Project Templates

Revit template files (`.rte`) are binary and firm-maintained inside Revit
itself — they can't be generated by a script or stored meaningfully as text.
This file is the **build manifest**: the checklist a template maintainer
builds the `.rte` against, and the checklist anyone auditing it diffs it
against later. If the live template ever drifts from this list, this list
wins — fix the template, don't update this file to match a shortcut.

One template per discipline, all derived from the same manifest so browser
organization and naming line up when models are linked together:

- `DovaFutures_Architecture_Template.rte`
- `DovaFutures_Structure_Template.rte`
- `DovaFutures_MEP_Template.rte` (Mechanical, Electrical, Plumbing share one — split later only if a discipline outgrows it)
- `DovaFutures_Interiors_Template.rte`

Master copies live in the firm library at `Families/00_Templates/` (see file
05) and are never edited directly on a live project — a project starts from
**Save As** off the master, and any template improvement gets proposed back
into the master, not left stranded in one job.

## Build checklist

### Project setup
- [ ] Project Information parameters present and blank/placeholder-filled:
      Project Number, Project Name, Client Name, Project Address, Project
      Status — matching the shared parameters in file 05.
- [ ] Phases set up matching the phase codes in the README (`CO`, `SD`, `DD`,
      `CD`, `CA`, `AB`), in that order, with `Existing`/`New Construction`
      phase filters pre-built.
- [ ] Worksharing enabled with discipline-relevant worksets pre-created
      (`Shell`, `Interiors`, `Site`, `Furniture`, `Levels & Grids`, `Links`).

### Levels & grids
- [ ] Starter set of levels named per file 03 (`00 - Ground Floor`, `01 -
      First Floor`, `RF - Roof`) as placeholders — real elevations get set
      per-project, but the naming pattern and level types must already be
      correct.
- [ ] Grid bubble size, level head family, and datum styles match the firm
      annotation standard.

### Views & view templates
- [ ] Every view template from file 06 pre-built and named correctly, with
      Visibility/Graphics, detail level, and scale already set — empty
      "shell" templates ready to apply, not built fresh per project.
- [ ] Default 3D view, default sheet list schedule, and a starter room/area
      schedule already placed.
- [ ] View filters for phase graphics (existing/demo/new) pre-built and
      matching the firm's standard line-weight and color conventions.

### Sheets & title blocks
- [ ] Firm title block family loaded, with Project Number/Name/Sheet
      Number/Sheet Name/Revision fields wired to the matching parameters.
- [ ] A blank cover sheet (`[Discipline]-000`) and drawing index sheet
      (`[Discipline]-001`) pre-placed.

### Families, materials, styles
- [ ] Core annotation families loaded (tags for every category the
      discipline uses, per file 05's `07_Annotation/Tags/` folder).
- [ ] Firm material library preloaded with the standard set from file 04 —
      not created ad hoc per project.
- [ ] Line styles, line patterns, fill patterns, and object styles match the
      firm graphic standard (line weights per discipline convention).
- [ ] `DovaFutures_SharedParameters.txt` (file 05) loaded into the template's
      shared parameter file path.
- [ ] Keynote file linked (firm keynote text file, not a per-project copy).

### Sanity check before publishing a template update
- [ ] Open a blank project from the updated template, place one sheet, apply
      one view template of each purpose, and confirm nothing throws a missing
      family/parameter warning on load.
- [ ] Bump the template's internal version note (a text note on a hidden
      "Template Info" sheet) so anyone opening it can see which manifest
      revision it was built against.
